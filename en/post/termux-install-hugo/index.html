Compile Hugo Extended with Go to work around the lack of pre-built binaries for Termux arm64

Important

It’s recommended to read through the entire article first to understand the overall process before proceeding.

Hugo doesn’t provide a pre-built binary for Android Termux’s aarch64 architecture on GitHub, so you’ll need to manually compile and install it within Termux.

Installing Go

Use the following command to install Go:

[~]$ pkg install golang

Check if the installation was successful — a normal output of the Go version number means success:

$ go version
go version go1.26.5 android/arm64

Compiling Hugo

In Hugo’s GitHub repository, the README provides the command for manual compilation. The source code is downloaded from GitHub, so make sure your network environment is fine, or use a mirror site.
Since the Hugo theme I’m using is hugo-theme-reimu, I need to install the Extended edition. Installing the Extended edition requires having GCC or Clang installed. If you don’t have it, run pkg install clang.
Then execute the following command to compile the Extended edition:

CGO_ENABLED=1 go install -tags extended github.com/gohugoio/hugo@latest

After this long list finishes, it should be compiled. My Kirin 970 chip only took 58 seconds to compile — give it a shot yourself!

Barring any surprises, the compiled Hugo binary will be in ~/go/bin/. Check it:

$ ~/go/bin/hugo version
hugo v0.164.0+extended android/arm64 BuildDate=unknown

If you see similar output, congratulations — it compiled successfully. For convenience though, run:

[~]$ cp ~/go/bin/hugo ~/../usr/bin/

And you can invoke Hugo from anywhere.

Conclusion

Not sure if it’s just me, but the Hugo binary downloaded from GitHub, even though it’s arm64, still wouldn’t run — so I had to compile it myself. If any experts can explain why, feel free to email me 😁

If you desperately need Hugo on Termux and have a poor build environment, drop an urgent email to kuqilin@88.com. If I see it, I’ll send you the compiled binary.
