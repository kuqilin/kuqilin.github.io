A record of my experience building a Hugo blog on GitHub Pages

Tip

Please read through the entire article before you start, to avoid some unnecessary mistakes.

Installing Hugo

Windows

Go to the official website and download the Hugo exe file, place it anywhere you like, then add it to your system PATH.

Linux

First install the Hugo binary — you can download it from the official website or use your package manager directly. Since apt updates are notoriously slow, Debian-based users are advised to download the deb package from the official website.

sudo apt install hugo    # Debian-based
yay -S hugo              # Arch-based

After installation, running hugo version should produce output similar to the following:

❯ hugo version  
hugo v0.164.0-ce2470e7012b5ab5fc4e10ebe4027e9f8d9e00dc+extended linux/amd64 BuildDate=2026-07-06T16:39:30Z VendorInfo=gohugoio

That means Hugo is installed.

Creating a Project

Use hugo new site <project-name> to create a project, for example:

❯ hugo new site myBlog  
Congratulations! Your new Hugo site was created in /home/kuqilin/myBlog.  
  
Just a few more steps...  
  
1. Change the current directory to /home/kuqilin/myBlog.  
2. Create or install a theme:  
  - Create a new theme with the command "hugo new theme <THEMENAME>"  
  - Install a theme from https://themes.gohugo.io/  
3. Edit hugo.toml, setting the "theme" property to the theme name.  
4. Create new content with the command "hugo new content <SECTIONNAME>/<FILENAME>.<FORMAT>".  
5. Start the embedded web server with the command "hugo server --buildDrafts".  
  
See documentation at https://gohugo.io/.

You should see a success message. Next, cd into the project folder myBlog and follow the prompts to configure it.

Creating or Installing a Theme

Obviously we can create our own theme, but for the sake of leeching convenience, just head over to Hugo Themes and pick one you like. Here I chose the hugo-theme-reimu theme.

There are several ways to install a theme — using Git Submodule is recommended:

cd myBlog
git init
git submodule add https://github.com/D-Sketon/hugo-theme-reimu.git themes/hugo-theme-reimu

You can also download the theme zip directly and extract it into the themes folder.

Then specify the theme in hugo.toml:

theme = "hugo-theme-reimu"

Configuring hugo-theme-reimu

The theme’s configuration files are located by default under themes/hugo-theme-reimu/config/_default/. We should not modify theme files directly, since they would be overwritten when the theme is updated. Instead, create identically-named files under config/_default/ in your project root to override them. Let’s copy params.yml (the theme parameters).

Basic Site Configuration (hugo.toml) 

baseURL = 'https://<your-username>.github.io/'
theme = "hugo-theme-reimu"
title = "xxx's Blog"       # Site title
locale = "zh-CN"           # Language
languageName = "简体中文"   # Language name
hasCJKLanguage = true      # Whether the site contains CJK characters

[markup.highlight]         # Syntax highlighting (required for code blocks)
guessSyntax = true
noClasses = false

[markup.goldmark.renderer]
unsafe = true

[markup.goldmark.extensions.passthrough] # Required for math formulas
enable = true
delimiters.block = [["\\[", "\\]"], ["$$", "$$"]]
delimiters.inline = [["\\(", "\\)"], ["$", "$"]]

unsafe = true allows using raw HTML in Markdown. passthrough enables the $...$ and $$...$$ syntax for math formulas.

Theme Parameter Configuration (params.yml)

Configure the theme’s various features in config/_default/params.yml. Here are a few key items:

Navigation menu:

menu:
  - name: home
    url: ""
  - name: archives
    url: "archives"
  - name: about
    url: "about"
  - name: friend
    url: "friend"

Personal info and avatar:

author: <your-name>
email: <your-email>
avatar: "avatar.jpg"           # Place under static/avatar/
banner: "images/banner.webp"   # Place under static/images/

Social links:

social:
  email: mailto:<your-email>
  github: https://github.com/<your-username>
  twitter: https://twitter.com/<your-username>

Sidebar and widgets:

sidebar:
  position: left  # Can be left or right
widgets:
  - category
  - tag
  - tagcloud
  - recent_posts

Comments (using Waline as an example):

comment:
  default: waline
waline:
  enable: true
  serverURL: "<your-waline-server-url>"

Enabled features:

toc: true                # Table of contents
dark_mode:
  enable: auto           # Follow system preference automatically
math:
  mathjax:
    enable: true         # Math formulas
show_update_time: true   # Show last updated time

For more configuration options (mouse effects, Live2D, fonts, loading animations, etc.), please refer to the official theme documentation.

Once configured, run hugo server -D to preview your site locally at http://localhost:1313.

Other Configuration

For other things like changing the mouse cursor, modifying fonts, post banners, post covers, site color scheme, shortcodes, friend links, and so on, please check the official documentation. I won’t go into detail here. hehe

Deploying to GitHub Pages

The core idea behind deployment is pushing the public/ directory — generated by Hugo’s build — to the <username>.github.io repository. GitHub Pages will automatically serve that repository’s content as a static website.

In other words, we need two repositories:

  • Source repository (e.g. hugo-build): holds the Hugo project source files (Markdown, config, theme, etc.)
  • Pages repository (<username>.github.io): contains only the static files from public/

Below I’ll cover two approaches: manual push and automatic deployment via GitHub Actions.

Method 1: Manual Push to github.io

The most straightforward approach — build locally with hugo, then push the contents of public/ to the pages repository.

1. Clone the Pages Repository 

git clone https://github.com/<your-username>/<your-username>.github.io.git public

If the public/ directory already exists (Hugo generates it when building), delete it first, then clone.

2. Build and Push 

# Go back to the source repository root and build
hugo

# Enter the public directory (which is now a clone of the pages repository)
cd public

# Commit and push
git add .
git commit -m "update"
git push origin main

Repeat the above steps every time you update your blog.

3. Write a Script to Simplify the Process

You can wrap the steps above into a script deploy.sh:

#!/bin/bash
echo "Building..."
hugo

echo "Deploying..."
cd public
git add .
git commit -m "update $(date '+%Y-%m-%d %H:%M:%S')"
git push origin main
cd ..
echo "Done!"

From then on, just run bash deploy.sh to build and deploy.

The advantage of this approach is that it does not rely on any third-party CI service — simple and direct. The downside is that it requires manual execution and you need to keep your local Hugo environment working.

Method 2: Automatic Deployment with GitHub Actions

A must-have for the lazy — push your source code to GitHub, and let Actions handle all the building and deploying automatically.

1. Create a Personal Access Token

To let Actions push code to the pages repository, you need a Token:

  1. GitHub → Settings → Developer settings → Personal access tokens → Tokens(classic)
  2. Generate a new Token, select the repo and workflow scopes
  3. Copy the generated Token (note: this Token is only shown once — make sure you save it)

Then, in your source repository, go to Settings → Secrets and variables → Actions, create a new Secret named TOKEN, and paste the Token you just copied.

2. Write the Workflow File

Create .github/workflows/hugo.yaml in the root of your source repository:

name: deploy

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
        - name: Checkout
          uses: actions/checkout@v4
          with:
              fetch-depth: 0
              submodules: true       # Needed if the theme is installed via git submodule

        - name: Setup Hugo
          uses: peaceiris/actions-hugo@v3
          with:
              hugo-version: "latest"
              extended: true

        - name: Build Web
          run: hugo

        - name: Deploy Web
          uses: peaceiris/actions-gh-pages@v4
          with:
              PERSONAL_TOKEN: ${{ secrets.TOKEN }}
              EXTERNAL_REPOSITORY: <your-username>/<your-username>.github.io
              PUBLISH_BRANCH: main
              PUBLISH_DIR: ./public
              commit_message: auto deploy

Explanation of each step:

Step Purpose
actions/checkout@v4 Pulls the source code; submodules: true also pulls theme submodules
peaceiris/actions-hugo@v3 Sets up the Hugo environment (extended edition, supports SCSS)
hugo Builds the site and generates the public/ directory
peaceiris/actions-gh-pages@v4 Pushes public/ to the pages repository

3. Push Source Code to Trigger Deployment 

git add .
git commit -m "new post"
git push origin main

Every time you push to the main branch, GitHub Actions will run automatically. You can check the build progress on the Actions tab of your source repository. A green ✅ means deployment succeeded — then visit https://<your-username>.github.io/ to see your updated blog.

Comparing the Two Approaches

Manual Push GitHub Actions
Workflow Run hugo locally + push manually Just git push the source
Dependencies Requires local Hugo installation No local environment needed
Best for One-off updates; can’t set up Actions Daily blogging — automation is the most hassle-free
Complexity ⭐ Simple ⭐⭐ Requires one-time Token and yaml setup

The two approaches are not mutually exclusive — you can use both simultaneously. Once Actions is set up, it handles daily automatic deployment, and you can still do a manual push whenever you need to.

And with that, building, configuring, and deploying a Hugo blog is complete 🎉
